# iGallery 首版设计

## 目标与边界

在 Raspberry Pi 上从 Immich 获取家庭照片，通过本地幻灯片网页和 Chromium kiosk 模式，将画面经 HDMI 输出到 BOE 画屏。NAS 短时不可用时，继续播放已缓存照片；Immich API Key 不进入浏览器、日志或 GitHub。

项目名称为 `iGallery`，目标 GitHub 仓库为公开的 `turingcat/iGallery`。当前工作目录保留不变。树莓派使用用户提供的连接信息，密码与 Immich 密钥不记录在项目文件中。

首版包含随机照片、指定单个相册、本地持久缓存、幻灯片、systemd 服务和 kiosk 部署说明。不包含 MT Photos、管理后台、人物/地点筛选、多来源播放或视频播放。

## 方案选择

1. **推荐：Python 服务 + 持久缓存 + 本地网页。** 可独立测试，密钥留在后端，断网仍可播放；需要维护小型后端。
2. 浏览器直接打开 Immich：实现最快，但没有可控的离线缓存，也不适合作为无人值守相框的稳定播放方案。
3. 接入多图库的通用相框平台：兼容面较广，但超出当前 Immich 单源需求，增加部署与维护成本。

采用方案 1，不提前构建通用 Provider 框架。

## 架构与组件

```text
Immich API
    |
    v
Python / FastAPI 服务
    |-- Immich 客户端：照片列表与 preview 缩略图
    |-- 缓存管理：图片、播放清单、定时刷新
    |-- HTTP 接口：本地照片列表与图片
    v
Chromium kiosk -> HDMI -> BOE 画屏
```

- Immich 客户端只负责请求与筛选图片；明确配置请求超时，保持 TLS 校验，不跟随携带密钥的跨主机重定向。
- 缓存管理负责刷新、持久化与恢复。浏览器只读取本地缓存，不在切图时访问 NAS。
- 前端使用普通 HTML/CSS/JavaScript，不引入前端构建工具；播放界面以照片为主体，不显示管理控件或密钥。
- 单进程服务运行刷新任务，避免多 worker 重复下载或争用缓存。

## 配置与照片来源

真实配置使用树莓派上的本地环境文件，设置仅服务账户可读的权限；仓库只提供不含真实值的示例。配置、缓存和临时文件加入 Git 忽略规则。

| 配置项 | 首版行为 |
| --- | --- |
| Immich 地址、API Key | 必填，只从服务端配置读取 |
| 播放模式 | 默认随机；可指定一个相册 ID |
| 缓存数量 | 默认 100 张，为缓存保留设定上限 |
| 切换间隔 | 默认 30 秒 |
| 刷新间隔 | 默认 600 秒 |
| 缩略图 | 固定使用 preview |
| 监听地址 | 默认 `127.0.0.1:8080` |

随机模式使用 `POST /api/search/random`；指定相册模式读取相册资产，从中选取至缓存数量上限的图片。下载使用 `GET /api/assets/{id}/thumbnail?size=preview`。开发时依据当前官方文档与实际 Immich 版本核对请求字段和必要权限，不把参考材料中的权限列表视为已验证事实。

只接收照片资产，跳过视频及无有效 ID 的条目，去重后下载。相册模式首版不实现特殊时间排序。API Key 使用满足上述接口的最小权限，不要求管理员权限。

## 缓存与错误处理

1. 启动时先载入已有清单；有效缓存可立即播放，后台再刷新。
2. 每次刷新请求照片列表，下载有效 preview 图片，验证响应内容后写入临时文件，再原子替换。缓存路径由程序生成，不直接使用上游文件名。
3. 已缓存的资产可复用。新清单只引用已成功缓存的图片，并以原子替换方式发布，避免断电留下半份清单。
4. 部分下载失败时，可用成功下载的图片与旧缓存补足播放队列；全部失败或上游返回空结果时保留旧清单。
5. 新清单发布后清理不再引用的图片，稳态缓存不超过设定数量。刷新过程可临时保留上一批图片，换批期间旧 URL 失效由前端跳过并重新拉取清单处理。
6. NAS 超时、断网或认证失败时，不清空缓存；日志只记录不含凭据的错误类别，下个刷新周期重试。
7. 首次启动没有缓存且无法连接时，显示简洁的等待提示，前端持续重试，不保持永久黑屏。

缓存清单损坏时忽略损坏记录并尝试重新获取；服务不会把缓存存在等同于 NAS 当前在线。

## HTTP 与播放行为

| 接口 | 用途 |
| --- | --- |
| `GET /` | 幻灯片页面 |
| `GET /api/photos` | 本地照片 ID、URL、切换间隔；不含上游地址和凭据 |
| `GET /api/photo/{id}` | 仅提供清单允许的缓存照片，拒绝任意路径访问 |
| `GET /health` | 服务存活、缓存数量、最近刷新是否成功；不暴露异常原文 |

首版不提供手动刷新接口或远程管理入口。配置变更通过编辑本地文件并重启服务生效。

前端预加载下一张，加载成功后才淡入切换，使用 `object-fit: contain` 保留完整画面，以黑色留边避免裁切家庭照片。坏图或过期 URL 被跳过；全部加载失败时保留最后一张并重试清单。播放一轮后重新获取清单；列表为空或请求失败时退避重试。单张图片也继续定期获取清单。

## 树莓派部署

- 优先原生 Python 虚拟环境 + systemd；首版不同时维护 Docker 部署方案。
- 后端开机启动并在异常退出后自动重启，配置和缓存目录在仓库之外，文件仅对所需账户开放。
- 图形会话启动 Chromium kiosk 访问 `http://127.0.0.1:8080`，启动前等待本地服务可用。
- 安装前检查树莓派架构、系统版本、图形环境、Chromium 路径和网络；按实际桌面环境配置自启动，不假定一定是 labwc 或 X11。
- 目标 HDMI 模式为 1920×1080；显示方向与实际画屏摆放现场确认，不在首版强制旋转。
- 配置 kiosk 时保留现有用户自启动条目，不覆盖整个文件；系统、网络或显示设置变更单独说明。
- Immich 地址属于 Tailscale 地址段。当前开发电脑的 ping API 已返回 HTTP 200，但树莓派的访问能力和 API Key 权限仍需实测。若不可达，先报告网络前置条件，不擅自安装或登录 Tailscale。

## 安全与公开仓库

密钥不进入任何 Git 提交、命令行参数、浏览器响应或错误日志。部署时不关闭 SSH 主机密钥验证；使用用户提供的密码仅用于本次连接，不将密码写入脚本。应用默认只监听回环地址，不向局域网开放照片与操作接口。

提交和推送前检查暂存文件，确保不存在真实密钥或树莓派密码。README 使用占位地址。由于密钥已通过对话提供，建议部署完成后轮换，并更新树莓派本地配置。

## 验收标准

1. 自动测试验证随机/相册请求、图片筛选、去重、超时及错误响应；默认测试不连接真实 NAS。
2. 缓存测试验证原子发布、数量上限、空结果/全失败保留旧缓存、部分失败、重启恢复和无效图片处理。
3. HTTP 测试验证前端响应不含 API Key、路径不能逃逸缓存目录、只提供允许的本地图片。
4. 浏览器验证正常切图、预加载失败、单图/空列表、清单换批、短时后端故障和重新连接。
5. 树莓派实测从 Immich 获取图片并在本地页面播放；暂停 NAS 访问后仍能播放缓存；重启服务后恢复缓存。
6. 确认 systemd 自动启动、桌面 kiosk 配置、1920×1080 输出；BOE 实际显示效果与设备重启后的全屏播放需要设备现场验证，无法观察时明确标记未验证。
7. 公开仓库包含代码、中文 README、配置示例、部署说明和 CI 测试，不含真实凭据或缓存照片。
