# iGallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user chooses delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现可在树莓派长期运行的 Immich 本地缓存幻灯片服务，并发布公开仓库 `turingcat/iGallery`。

**Architecture:** 单进程 FastAPI 服务通过 Immich 客户端刷新持久缓存，网页只消费本地清单与图片。systemd 启动后端，桌面会话启动 Chromium kiosk；故障时继续显示已缓存照片。

**Tech Stack:** Python 3.11+、FastAPI、uvicorn、httpx、Pillow；pytest、pytest-asyncio；普通 HTML/CSS/JavaScript；Node 内置测试运行器与 Playwright 开发验证；systemd、Chromium。

**Spec:** `docs/superpowers/specs/2026-10-06-igallery-design.md`

## Global Constraints

- 项目名称为 `iGallery`，目标 GitHub 仓库为公开的 `turingcat/iGallery`。当前工作目录保留不变。
- 首版包含随机照片、指定单个相册、本地持久缓存、幻灯片、systemd 服务和 kiosk 部署说明。不包含 MT Photos、管理后台、人物/地点筛选、多来源播放或视频播放。
- 单进程服务运行刷新任务，避免多 worker 重复下载或争用缓存。
- 默认缓存 100 张、切换间隔 30 秒、刷新间隔 600 秒、缩略图固定 preview、监听 `127.0.0.1:8080`。
- 密钥不进入任何 Git 提交、命令行参数、浏览器响应或错误日志。
- 原生 Python 虚拟环境 + systemd；首版不同时维护 Docker 部署方案。
- 所有自动测试使用临时目录和假凭据，不访问真实 NAS。
- 保留既有 `AGENTS.md` 和 `CLAUDE.md` 内容；不进行无关修订。
- 设计要求英文标识符与中文用户文档；新增源码默认 ASCII，中文说明文档沿用设计文档语言。

## Review Focus

1. 带 `/api` 或尾斜杠的 URL 与非 HTTP(S) 地址：归一化合法地址，拒绝非法配置，不在异常中包含凭据（Task 1、2）。
2. 上游 ID、跳转响应、非图片响应：拒绝路径注入和重定向，不缓存 HTML 错误页，不把密钥发送给另一主机（Task 2、3）。
3. 清单发布失败或旧图片尚在浏览器队列：保留可恢复的旧清单，不提前删旧文件；浏览器跳过失效 URL（Task 3、5）。
4. 空图库、单图、全部图片加载失败或清单请求挂起：持续尝试恢复，不清屏、不停止轮播（Task 3、5）。
5. OS/桌面版本差异、网络缺失、重启中断：安装前确认兼容性，保留自启动文件，遇到网络前置条件不足时报告而非擅改网络（Task 6、7）。

### Task 3: 持久缓存与故障恢复

**Files:** `igallery/cache.py`, `tests/test_cache.py`。

**Interfaces:**
- Consumes: `Settings`, `ImmichClient.list_ids()`, `ImmichClient.download()`。
- Produces: `PhotoCache(settings: Settings)`；同步 `load() -> None`, `photo_ids() -> list[str]`, `path_for(asset_id: str) -> Path | None`；异步 `refresh(source: ImmichClient) -> bool`；字段 `last_refresh_success: bool | None`。
- 清单格式固定 `{"version": 1, "ids": ["uuid"]}`，图片保存为 `{uuid}.jpg`，只提供当前清单允许的 ID。

- [ ] **Step 1: 写失败测试。** 生成小型真实 JPEG fixtures，用 fake source 实现上述两个异步方法。断言刷新后图片与清单存在、UUID 去重、第二实例 `load()` 恢复相同 ID、照片可由 Pillow 重新打开。

```python
@pytest.mark.asyncio
async def test_failed_refresh_preserves_cache(settings, good_source, failing_source):
    cache = PhotoCache(settings)
    assert await cache.refresh(good_source)
    before = cache.photo_ids()
    assert not await cache.refresh(failing_source)
    assert cache.photo_ids() == before
    restored = PhotoCache(settings)
    restored.load()
    assert restored.photo_ids() == before
```

- [ ] **Step 2: 红灯。** `.venv/bin/python -m pytest tests/test_cache.py -v`；预期缺少 PhotoCache。
- [ ] **Step 3: 实现。** 同目录临时文件 + `os.replace` 发布图片与清单；清单成功替换后才更新内存列表和清理旧文件。Pillow 解码并转 RGB JPEG（处理 EXIF 方向），将最长边限制 1920、quality 85；验证时拒绝损坏文件与解压炸弹。图片处理通过 `asyncio.to_thread`，顺序下载无需并发池。旧文件复用，成功新图片优先，旧 ID 补足至上限；没有成功候选时保留旧清单并返回 False。无有效清单时忽略孤儿图片，后续成功刷新清理。

```python
# Ordering invariant: persist before publishing, remove only afterwards.
os.replace(manifest_tmp, manifest_path)
self._ids = next_ids
# Delete only files not referenced by the now-published manifest.
```

- [ ] **Step 4: 补全绿灯测试。** 覆盖空结果、全失败、部分失败、损坏 JPEG、恶意 ID、清单坏 JSON/超限、丢失缓存文件、已有缓存复用。通过 monkeypatch 让清单 `os.replace` 失败，断言内存与磁盘旧清单不变、旧文件仍存在；下一次刷新能恢复。清理不能追踪缓存外的符号链接或路径。用 caplog 断言失败日志不含假 Key。
- [ ] **Step 5: 运行与提交。** `.venv/bin/python -m pytest tests/test_cache.py -v`；`git add igallery/cache.py tests/test_cache.py && git commit -m "feat: persist bounded offline photo cache"`。

### Task 6: 树莓派部署模板、文档和 CI
